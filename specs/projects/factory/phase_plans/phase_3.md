# Phase 3 — Message log

Base `5921e35`. Deliver the shared message store and its offline reader. A sender's text becomes eligible for delivery at one observable point, the complete `ok` line. An outcome belongs to one recipient. A crash between two appends must leave enough evidence for the next process to tell what happened.

The wire format and public methods are in [message_log.md](../components/message_log.md). User-visible guarantees are in [functional_spec.md §§8.5–8.7](../functional_spec.md). [cli_skill.md §§1–2](../components/cli_skill.md) specifies checkout selection and offline reading. [keeper.md §§2–6](../components/keeper.md) names the next consumers. This phase does no delivery, queue scheduling, keeper startup, or crash-time selection of the next recipient. The latter belongs to #168.

## 1. Cutover and files

Phase 3 leaves every v1 command and its tests in place. In `skill/scripts/factory.py`, `queue_message` (v1 `say`), `cmd_wait` including `--seen`, `report_pending_messages` (v1 `up`), `cmd_status` and `cmd_inbox` still use `Inbox`. Phase 4 changes `inbox` together with `say`, its first v2 writer, moves the messaging parts of `status` and `up` in the same change, and removes the old `wait` and `say` paths and `Inbox`, `InboxDamage` and their remaining exclusive code and tests (@operator's cutover decision, recorded in implementation_plan.md: old v1 files stay byte-for-byte and are read with the retained v1 build). No migration, dual write or artificial `delivered` outcome for a v1 acknowledgement. This timing keeps both the v1 operator history and herdr session isolation intact until the relevant cutovers.

Production changes belong in `skill/scripts/factory.py`, coverage in `tests/test_factory.py`. Update `components/message_log.md`, `components/testing.md` and the Phase 3/4/5a bullets in `implementation_plan.md` to capture the approved timing and fault behavior. Keep the existing CLI help and references until the command changes. The same tests run in the fake and real CI jobs. The store and reader tests need only a private temp directory.

## 2. Interface and ownership

Keep the signatures of `Log.read(offset=0) -> (records, end)`, `Log.add(sender, to, text, kind="say", file=None, meta=None) -> (id, end, warning)` and `Log.out(box, id, to, o, **extra) -> bool`. `Log(state)` takes the explicit team directory. Constructing it has no filesystem effect. Code resolving the team passes the path in. An independent `Log` instance can open the same directory in another process.

Use `Box` for the replayed log. Its `msgs`, `uncommitted`, `outcome`, `pending`, `last_to`, `last_from`, `briefed`, `last_note`, `quiet_note` and `ready_note` follow the component. Byte offsets always come from the reader. The call sequence is `records, end = log.read(box.offset)`, `box.apply(records)`, then `box.offset = end` after successful application. Never calculate offsets by serializing the parsed dicts. Start a full box at zero and retain reference checking on every subsequent refresh. Use `Box(path)` for a full history. `Box.for_message(path, id, recipients, offset)` initializes a partial outcome-only view for Phase 4's caller of `add`. Seed the committed ID, recipient set and implicit waiting outcomes. Apply only outcomes for this ID, verify their recipient and ignore other IDs. This view cannot authorize writes or validate a prefix.

Lift `Inbox.private_open` to a shared module helper. Have the existing v1 callers use it and preserve their permission behavior. Reuse its no-follow, nonblocking open and regular-file check. Writers create private directories (0700) and files (0600); only change permissions on an opened, verified file. The v2 state directory, log and message-directory components must never be followed through a symlink. An owner-supplied cache base can itself refer to a physical path via a symlink, as v1 permits. Read-only inbox inspection must not chmod or rewrite data, create a missing team, update the checkpoint, or remove files.

## 3. Locking, reads and validation

The state directory on a local filesystem is the team lock. Open it with `O_DIRECTORY | O_NOFOLLOW`. Writers take `LOCK_EX` on that descriptor for prefix verification, ID/transition selection, appends and checkpoint replacement. Readers take `LOCK_SH` for their snapshot. Use that same descriptor for file operations within the critical section. Future `team.json` and `sessions.jsonl` operations share this lock. Keep `hc` calls, subprocesses and waits outside it. If an exclusive flock fails, preserve the original errno and state path and suggest setting `XDG_CACHE_HOME` to a local path.

Only writers create directories. A reader that finds no state directory returns an empty snapshot at offset zero. Before the first ordinary durable commit, sync the directory entries that make the state reachable, including their containing directories. A retry must cover an earlier initializer that created directories and died before syncing them. For nonzero offsets first check that byte `offset - 1` is LF. Keep a private `Box._reset()` that clears cursor, replay state, pending message and indexes before a validated replacement snapshot is applied to the **same** box. The successful refresh sets its offset to the reader's new end. Never leave a half-refreshed box usable after damage.

Read UTF-8 bytes split on LF. Require every record, including the last, to end with LF. Blank lines, invalid UTF-8/JSON, nonobjects and unknown record types cause `LogDamage(path, one_based_line, reason)`. An empty log is valid. A trusted offset is a byte boundary previously returned by this log; offset past EOF, or inside a line, fails with a diagnosis. On tail errors compute the absolute line number from the prefix if needed. Ordinary tail reads need only the suffix. A full read validates structural rules and references before returning anything, even if inbox requests just one message.

| Record | Validate before accepting |
|---|---|
| `msg` | Positive integer ID, strictly greater than all previous message IDs (reject bool); UTC timestamp, nonempty sender, nonempty list of distinct nonempty recipients excluding sender, kind `say/brief/note`, string text. A file when present is an absolute string path. Note metadata when present is an object. Allocate exactly previous highest message ID + 1 on new writes. Preserve text including quotes, embedded newlines and the absence or presence of its final newline. |
| `ok` | Its positive integer ID equals that of the immediately preceding `msg`. A standalone or second `ok` is damage. A complete `msg` with no `ok` is valid and consumes its ID, including at EOF or before the next message. No reader exposes that message. |
| `out` | Positive integer ID naming a committed message, actual recipient, known outcome and timestamp. Check the field types from the component (e.g. `started` bool/null and integer `turn` on delivery). Apply the outcome state machine in §5. A malformed reference or record anywhere prevents new appends. |

Use the same field/reference checks for full replay and new writes. `add` raises `ValueError` for invalid sender, recipients, text, kind, file or metadata; `out` raises `ValueError` for an invalid ID/recipient, outcome, reason or receipt fields. Check types before writing. Require a nonblank `why` for `dropped`/`unconfirmed`, and a specified queue reason from the component; `busy` is reserved for the possible §8.3 fallback. The 64 KiB user-message limit belongs to Phase 4's `say`. Historical invalid records raise `LogDamage` with the actual path and line. A tracked `msg` waiting for `ok` carries over between replay batches; update `uncommitted` when it is committed. The raw list returned by `read` retains text even when a box evicts its own copy. Do not `pop("text")` from a dict the inbox renderer still owns.

### Checkpoint

`log.check` is a disposable proof of validation, never commit evidence. Match regular-file inode, exact size and nanosecond mtime of `log.jsonl`; require valid integer fields and plausible nonnegative `last`. On a match, `add` can allocate the next ID without reading log bytes. Otherwise replay from byte zero and check references using a full box. An altered, unreadable-as-JSON, missing or stale checkpoint costs one replay. Treat unsafe file types/paths as errors. A missing log and absent checkpoint is the empty store; if only the checkpoint remains, diagnose the missing log before allocating ID 1. For `out`, refresh the caller's box across intervening appends while still holding the write lock. On prefix mismatch rebuild from the validated current file rather than applying an old offset to its replacement.

After a successful append, write current stat fields and highest `msg` ID to a private sibling temporary file and atomically replace `log.check`. A checkpoint-write failure after a committed append must leave the result committed. Skip the optimization and allow the next writer to validate the log. No directory or checkpoint fsync is required for this cache. Tests must cover inode replacement and a one-byte early edit with an explicitly changed nanosecond mtime, independent of how quickly the filesystem timestamps successive writes. The stat check assumes cooperating writers use the lock and an outside editor does not deliberately restore size, inode and mtime after tampering.

## 4. Append, commit and fault classification

For each line record the starting size, encode the entire JSON object plus LF once and loop `os.write` on the verified append fd. Continue on a positive short write. Zero progress or an exception enters recovery. After the last byte, fsync the file, then the directory. On a write or sync failure attempt to truncate to the starting size and fsync again. Under the same exclusive lock, examine the *actual tail from the starting size* with a read-capable fd. The append fd is normally write-only.

| Tail after recovery | `msg` append in `add` | `ok` append in `add` | Outcome append in `out` |
|---|---|---|---|
| Original size, no new bytes | `NotStored(partial=False)` | Same; preceding message stays uncommitted | Same; previous outcome stands |
| Exactly the complete intended line | `NotStored(partial=False)`, whole uncommitted message; stop before writing `ok` | Return ID and offset with the component's “stored and will be delivered … Do not resend” warning | `sending`: raise `NotStored(partial=False)`, leave box offset before this record, skip the checkpoint, do not hand to hc; the next refresh sees it. Other outcomes: written |
| Any other readable tail | `NotStored(partial=True)`; subsequent reads diagnose damage | Same; no message can be delivered through an incomplete commit | Same; refuse to extend a damaged log |

Normal success on `msg` proceeds to `ok` under the same lock. A synced `ok` returns the ordinary stored result. A complete `ok` verified after a failed sync/rollback is the only stored-with-warning case. **If the final read-back of the attempted `ok` fails**, raise `OSError` chained from that I/O error. Include the attempted message ID, `log.jsonl` path and the exact guidance “storage outcome unknown; do not resend; check inbox after repair”. Leave the checkpoint alone and return immediately. There is no persisted unknown outcome, no `NotStored` result and no retry. The complete `ok`, if present after repair, remains authoritative. Qualify the component’s “reports it stored if and only if” statement by the ability to verify the tail. When read-back of a `msg` fails before any `ok` attempt, that message is certainly uncommitted; report `NotStored(partial=True)` because an incomplete row may remain. An unreadable outcome append must likewise surface the I/O error and must not authorize a handoff or further append. A process killed after complete `ok` and before reporting can leave a committed message with no sender-visible result.

## 5. Outcomes and indexes

There are two real callers of a drop. Let `Log.drop_queued(box, names: set[str]) -> int` handle shutdown's batch in one exclusive section. Refresh once, then drop only pairs still queued to one of those names; return the count actually written. Share its internal locked single-record append with `out`. Send-result handling continues to use `out(..., "dropped", why=...)` for an in-flight refusal. If the batch fails partway, earlier final records stand; repeating the batch skips them. The eventual `down` caller owns printing and terminal teardown.

Fresh committed pairs start at `queued (waiting)` without an `out` line. Under the exclusive lock, refresh the box, then conditionally append at most one outcome. The current state decides whether the append can proceed even if two writers have stale copies. A `sending` claim requires `queued`; a receipt or uncertain send requires `sending`; `queued` may change reason or follow a known pre-typing refusal from `sending`; `dropped` may follow queued or sending. A final pair never changes. Duplicate attempts at the current state/reason and attempts on an already-final pair return False. Keep all five persisted outcomes distinct from command-only `refused` and `not stored`. Advance the supplied box on a successful append; a fresh reader and that box must agree.

**Replay rule.** `Box.apply` raises `LogDamage` on an illegal recorded transition, preserving the log for repair. This includes `queued → delivered`, `queued → unconfirmed`, a second `sending`, and any row after a final outcome (even a repeat of that final result). A `queued → queued` change of reason updates the pair. Repeating its current reason is idempotent, including the initial implicit `waiting` state. A normal stale writer returns False before appending; an impossible transition already on disk is evidence to diagnose. For example, ignoring a stored `delivered` that lacks its `sending` claim would expose the pair for redelivery.

- Keep IDs, recipients, metadata, file path and last outcomes after discarding text from all-final messages. `pending(to)` includes queued and sending pairs, sorted by ID and recipient order. It exposes pending candidates; Phase 4 decides what to dispatch.
- `last_to(name, sender=None)` chooses the newest message by ID with a delivered outcome for that name. `last_from(name)` chooses the newest committed message by that sender. `briefed()` collects the actual terminal IDs in delivered brief outcomes.
- For member notes, return the newest committed member-note metadata for its terminal. For quiet/ready notes return the newest matching committed message whose operator outcome is not dropped. If the newest is dropped, look back to an earlier qualifying note. Never infer notes from unrelated text. Match the metadata fields written by keeper.md §§5–6; an `exit` note need not carry `since`.
- `down`'s future queued-only drop is distinct from a send result that may legitimately turn a `sending` into `dropped`. Test conditional, lock-scoped queued-only selection with stale callers; do not implement the Phase 5 `down` command here.

## 6. Message files

Use `managed_file(state: Path, sender: str, path: Path) -> bool` for membership/eligibility, `Log.remove_delivered_file(box, id) -> str | None` after a delivered receipt (an unlink warning with its path, or None). `Log.leftovers(now: float | None = None) -> tuple[list[dict], list[str]]` returns the remaining rows and I/O warnings. Each row has `sender`, `path`, `age_s`, `id` (null if never stored), and `outcomes` keyed by recipient. Use current epoch time when `now` is omitted. A small formatter next to the scanner produces the cold-start lines and one reminder. A missing file needs no warning. For deletion, open the managed directories relative to the verified state directory with no-follow directory descriptors and unlink the basename relative to the sender's descriptor; recheck the directory entry without following its last component. This prevents a switched directory symlink from redirecting the unlink to an external folder.

Build the file helpers against a state directory and committed log facts, independent of `hc`. The immediate cleanup caller in Phase 4 and cold-start caller in 5a/5b need the same ownership predicate. Keep absolute lexical paths for comparisons. A removable file must be a regular file directly in `state/messages/<recorded sender>/`, have a basename matching `[A-Za-z0-9-]+\.[A-Za-z0-9]+`, and have no symlink in the state/messages/sender chain. Never resolve an external argument into an apparently managed one, traverse `..`, or unlink a symlink. A sender-supplied path outside that exact folder remains caller-owned. A file in the managed folder with an invalid name is rejected by the eventual `say`; Phase 3 supplies the predicate and tests.

Use the newest committed message with the same sender and path for each decision. Unlink only when **every** recipient is `delivered`, even if all the others have final outcomes. `unconfirmed`, `dropped`, pending and never-stored files remain. Do not delete an older message's path after a newer message claimed it. Recheck under the team lock before unlink to serialize competing log updates. Owners follow the unique-file convention of §8.7. Handle a concurrently disappeared file as already gone. Report an unlink I/O failure once to the caller without rewriting outcomes.

The cold scanner walks regular files in per-sender directories, lists remaining paths in stable order with age, ID and recipient outcomes or “never stored”, and emits the “Check before resending or discarding” reminder once. It removes fully delivered managed leftovers silently. It preserves irregularly named regular leftovers for inspection; ignore symlinks and nonregular entries. An external path is never swept. Implement and test the two helpers here; the keeper and new `up` supply their call sites in their own phases.

## 7. Reading the inbox

`inbox_rows(log: Log, name: str, count: int = 10) -> list[tuple[dict, dict]]` is the Phase 3 inbox reader. The caller supplies the recipient name and explicit log. Validate a positive integer count and nonempty name. From one validated snapshot, select the last N original committed messages addressed to that name and return them in ascending ID order, paired with that recipient’s current outcome. Include original text even after a final outcome; include the reason for a queued outcome. Return an empty list on no match. Propagate a read/damage error before returning any rows. The function performs no discovery, CLI parsing, output, acknowledgement or state change.

**Phase 4 handoff.** Wire the reader into `inbox [N] [--for NAME]` and implement rendering and caller/checkout resolution with cli_skill.md §1. Keep actual CLI/help, labelled caller, renamed operator, multiple cores and exit-code tests in that phase. Offline candidates are non-symlink checkout state directories containing `log.jsonl` or `team.json`; the v1 prompt dirs contain neither. Prefer newest actual log mtime; if every candidate is metadata-only, use newest `team.json` mtime. Break ties by pathname, name the selection on stderr if there are several, and surface unsafe log paths as errors. Phase 3 does not introduce a resolver or CLI fallback.

## 8. Build order and proving tests

1. **Store and full reader.** Introduce the shared file primitives, exceptions, schema validation, `Box` replay, and `Log.read/add` with the commit rule. Test a fresh log, monotonically increasing IDs across reopen, Unicode/newlines round-trip, uncommitted IDs, wall-clock UTC timestamps, shared/exclusive locking, private modes, unsafe paths, every malformed record/reference, truncated offset and exact 1-based diagnosis. Check a damaged prefix blocks even a valid later row and leaves the bytes intact.
2. **Checkpoint, fault and concurrency tests.** Implement the append recovery matrix and prefix shortcut. Eight child processes add 25 messages each; assert all 200 IDs and adjacent `ok` rows. Use test-side patches of the module's existing write/sync/truncate functions. Cover multiple positive short writes, then failure/zero progress, file and directory sync failures, successful truncation followed by failed sync, failed rollback with empty, complete and partial actual tails, failed checkpoint publication, complete-but-unsynced `sending` versus `delivered`. Control a child through a pipe/barrier in the test, kill it while holding the lock before `ok`, then reopen with another process. Repeat immediately after complete `ok`. No production pause environment variable is needed. Test no log bytes read on a matching checkpoint, whole-file validation on stale inode/length/mtime or invalid cache; alter line 3 of a multi-MiB log. Force read-back failure with a whole `ok` left visible; assert the ID/path diagnostic, unchanged checkpoint and no second append. Restore reads and recover that one ID exactly once.
3. **Transitions, derived facts and files.** Exercise two full boxes of different ages attempting the same claim/finalization. Test conditional drops, nonfinal reason changes, retained references after final text eviction, every derived query, member notes versus quiet/ready notes, and ignored unrelated outcomes only in a partial box. Verify file lifetime on mixed-recipient outcomes, recovered all-delivered files, newer uses of one path, external/symlink paths, invalid basename, unlink failure and a file never logged. Inject each forbidden history transition, verify its first bad line and that a subsequent writer leaves all bytes untouched. Replay identical repeated queued reasons as a harmless no-op.
4. **Offline reader and v1 compatibility.** Call `inbox_rows` directly in a temporary store. Cover default 10 and explicit positive counts (including more than 100), per-recipient outcomes on mixed recipient lists, oldest-first order within the selected tail, original multiline text after eviction, nonrecipients, hidden uncommitted messages, empty results and damage anywhere before result publication. Verify no hc call, chmod, new file or checkpoint update on reads. Run the existing v1 CLI, inbox, wait, launch and status tests as written. Run `python3 tests/test_factory.py` and `FACTORY_TEST_HC=real python3 tests/test_factory.py` with Phase 2's private-core harness.

Phase 3 is ready for design review when the fault results agree with the visible bytes, unrelated sends never inherit another recipient's outcome, and every v2 reader can recover the same history solely from the log. Power-loss survival of an unsynced complete commit cannot be demonstrated by killing a process; the caller warning states that limit.

For the process-death test, the child wraps its own `Log._append` in the test process, signals the parent after the first line is synced, and blocks on a pipe before the second append. The parent waits for that signal, sends SIGKILL, reaps the child, then opens the log from a different process. For the after-commit case pause after the real second append returns. Update the `out` transition contract and queued-only batching in message_log.md, and replace the old production pause-variable instruction with the child-side patch in testing.md §2.
