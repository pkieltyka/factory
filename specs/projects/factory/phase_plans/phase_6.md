# Phase 6 · Keeper notes and autonomy (#171)

**Outcome.** When a briefed member blocks, errors or exits, the operator learns what happened. When a team stops making observable progress, it gets one quiet note. An optional local command can subsequently wake it for ready work. All three use the existing keeper, log and operator terminal. A keeper can load an updated Factory build without abandoning a send or losing its pane.

Plan baseline `ba22579`, including Phase 5b layout, recovery and cleanup. @lead-dev-2 writes on `peter/171-notes-autonomy` following @architect’s approval of this plan. @lead-dev-3 follows and @architect-2 reviews the finished implementation. The behavioral contracts are [functional spec §§8.4–8a and 10](../functional_spec.md), [keeper §§2–8](../components/keeper.md) and [message log, derived facts](../components/message_log.md). The multi-ticket runs with a tracker, reviewer, CI and human-free merges belong to Phase 9. Phase 6 can be proved with fake agents, hc and rodeo.

## 1. Extend the existing tick

In `skill/scripts/factory.py`, keep `Keeper(state, hc, clock=time, emit=print, spawn=None)`, the one directory lock for the log, the per-recipient send slots, the beat and the one-second tick. `View.member_terminals()`, `View.state/terminal/finished`, `Hc.keep_off/label`, `Box.last_note/quiet_note/ready_note/briefed/last_to/last_from`, `Config.quiet_grace/ready_every/ready_check` and `update_team(state, **changes)` already exist. Use them through their normal entry points. Changes also touch `tests/test_factory.py`, `specs/projects/factory/components/keeper.md` and, for the replay detail below, `components/message_log.md`. Phase 7 (#172) owns skill text, including `skill/SKILL.md` and `leading.md`. No new CLI, queue, daemon or dependency.

1. Touch the beat. Check the installed version when due (§5). Settle sends and collect completed ready checks. A ready result cannot change the log here because its authority depends on the refreshed state below.
2. Read team metadata, reload local config on its existing stamp, take the team-filtered view, refresh the full box, and update the operator null timer as today. Treat a missing/unreadable team or log, an unavailable core, and an invalid config as an interruption to a quiet interval. Preserve existing delivery recovery. Disable ready-check launches and invalidate any outstanding ready result when the current config fails to load, even if the previous Config object remains available for delivering ordinary messages.
3. With a healthy view and log and `team["up"] is True`, maintain member labels and generate member notes, then evaluate quiet and the ready check. If down, finish ordinary pending delivery under the existing exit rule. Skip new autonomy work while draining for upgrade. After each successful `log.add`, call `log.refresh(self.box)` before making any further decision, including delivery in this tick. A visible commit warning is still a commit. On storage error use the existing log fault and reload path, so the actual committed records decide what happens next.
4. Dispatch through `_deliver → _claim → _send` only. Keep the existing `_settle_result` special case for a definite pre-typing refusal of a quiet/ready note. Finish with the changed title (§5). No shell, tracker or log lock spans a send. Workers never write state or pane lines. The tick still services unrelated recipients during a held send or ready check.

## 2. Member notes

Iterate the configured members and use their selected terminal from the same team view. A member with `factory.down` is stopping. Ignore it for notifications, including a still-live record mid-stop. For a live briefed member with `keep` set, call `hc.keep_off(address)`; update `factory.last` only when a non-null reported state differs from the label. These are housekeeping operations on that member, independent of whether there is an operator to notify. An hc race on one terminal gets a bounded diagnostic and another observation next tick; it must not suppress other members or ordinary delivery. Skip strays and foreign terminals.

A reachable operator is a live `view.operator` with non-null OSC status. A blocked operator is reachable: an ordinary member note may wait for it. Without a reachable operator, do not originate a member note. On return consider the current episode. Never invent transitions during a polling gap. Nothing is sent for an unbriefed member. For a ready member:

| Observation | Durable identity in note meta | Text from known facts |
|---|---|---|
| `blocked` | `what="blocked:"+kind` (empty suffix if absent), `about=name, term=address, since=status_ms` | Name, kind, optional status message, and where to answer. |
| `error` | Same fields with `what="error"` | Name and reported error if present. |
| `gone` | `what="exit", about=name, term=address` | Exit code/signal or reported reason, last observed state or “state unknown”, latest delivered message from this operator if any, and `factory.py up NAME`. Use `view.terminal(name) or view.finished(name)`. A reported terminal with null status is the shell case. A never-reported terminal is starting. |

Compare to `box.last_note(address)` by episode, before appending. An exit has no `since`. A repeated status with a changed kind or a new `status_ms` is a new episode. A restart in the same episode reuses its committed note even when delivery is still pending. Reuse the cause formatting in `interrupted_line` where shared, keeping the member note's operator-sender filter. Persist `kind="note"` and only the documented meta. `_claim` and `cmd_inbox` already render factory notes by kind. Use the reserved sender `factory` for all keeper notes. Keep the note prefixes shared with Phase 7: `@x is blocked`, `@x hit an error`, `@x exited`, `@x was lost`, `team quiet` and `ready work`.

## 3. Quiet detection, rearming and freshness

Use one pure `quiet_now(view, box, cfg, wall_now, monotonic_now, inflight, op_null_since) -> bool`. Timers and deadlines use monotonic seconds. Terminal creation/status timestamps are epoch milliseconds and compare only to `clock.time()`. Require reachable operator, no operator or team member working, no recently starting member (less than `LAUNCH_TIMEOUT` old), no in-flight or persisted sending pair, and no currently deliverable non-autonomy head. Evaluate the same first-head/brief/supersession policy and `decide` that delivery uses. Filter quiet and ready notes *before* selecting heads so a quiet note cannot make itself ineligible or hide a deliverable item behind it. A member blocked, gone, unbriefed or stuck starting can coexist with quiet. A member note capable of delivery is real pending work for this predicate. Require an unblocked operator to originate either autonomy note.

Let `q = box.quiet_note()`. A committed non-dropped q suppresses another quiet note for its interval. Save `meta={"what":"quiet","turns":{address: turn, ...},"deliveries":box.deliveries}` with live member terminal turns. Rearm on observed member working, a new live member address, an increased member turn (hc increments it on leaving working), or delivery of any non-note pair after q committed. Operator turns and factory notes do not rearm. Test receipt order independently of message ID: a message held for a blocked member can predate q and be delivered after it. In `Box._reset`, set `deliveries` to zero and increment it on each accepted `delivered` outcome for a non-note. Replay produces the same count, even for several recipients of an older message. Compare the current count to the quiet note’s saved count. This single integer also detects delivery between grace samples. Require `deliveries` on every quiet note generated here. Replace keeper.md §6’s later-ID comparison with this counter and supply the counter in test fixtures that stand in for a generated quiet note. Skip the counter in `Box.for_message`, which lacks message kinds. There is no new record type, timestamp ordering or separate state file.

Count continuous quiet starting with the first qualifying observation. Reset the grace on real activity, including a turn bump or a receipt between two apparently quiet samples. Track the prior observed member turns/addresses and delivery count to detect a change before the first note as well. After grace (default 120 s) add exactly one quiet note if the operator can take it. If blocked through the grace, re-evaluate when it unblocks. Produce one line per member with a terminal record, reporting state, age where known, last received ID/sender and sent ID/recipients, or “none”. Use only metadata, never inspect chat bodies or infer an assignment. The snapshot and grace survive an operator-only response without causing a second note. A keeper restart restarts timers, and recovers the told state from the log.

For `quiet` and `ready` set `still_true` in the actual `_deliver` call to `decide` (currently omitted, so it defaults to true). Check the current team, operator availability, quiet predicate and current interval right before handing off. Refresh the log and team view for this exceptional dispatch if other work intervened; count the pending candidate as neither activity nor an in-flight send. A stale candidate is `dropped`, never put through the operator's normal blocked/gone/latch path. In `_deliver`’s bulk loop, record a queued autonomy note behind an ordinary operator head as `dropped` with reason `no longer true` when the operator is gone. Apply the normal bulk outcome to the other pairs. Quiet/ready entries recovered at startup get the same checks. Once a fresh note is handed to hc, a later hold on `draft_wait` can legitimately make it arrive late. A certain pre-typing refusal drops it; a transport receipt or uncertain attempt is final. Without a dropped-note retry delay, repeated immediate refusals can loop on the results wakeup: reset quiet grace for a failed quiet attempt and keep the normal check interval for a failed ready attempt.

## 4. Ready check

Only the owner's `Config.ready_check` from top-level `factory.toml` is executable. An example in `factory.toml.sample`, if supplied, is a comment above the first table. The keeper never executes a command from the brief or interprets tracker formats. After a quiet note reaches `delivered` or `unconfirmed`, and while still quiet, reachable and unblocked, set the first deadline to now + `cfg.ready_every` (default 300 s). No check while q is pending, sending or dropped. Reset the schedule for a new quiet interval; restart also waits a full period. At most one job runs, even when ticks are woken by other sends.

Off the delivery thread run `["sh", "-c", cfg.ready_check]` with `cwd=self.team["root"]`, `stdin=DEVNULL`, stdout captured, `stderr=DEVNULL`, and `READY_TIMEOUT` (30 s). Treat execution/decoding failure, timeout and exit other than 0/1 as unknown. Do not print output in the pane. Use the injected `spawn` and one result queue. The worker puts a three-field `("ready", job_key, (exit_or_error, output))` on it. `_drain_results` recognizes this shape before unpacking four-field send results, including a send to a member named `ready`. Bind the job to its quiet note ID, local config stamp and observed eligibility interval. On completion clear the running slot. Re-evaluate using current facts before acting on **either** work or no-work. Discard results from a changed command, interval, unreachable/down team or upgrade; an old “none” must never clear a newer report. Do not run more than once per configured period.

| Valid current result | Effect |
|---|---|
| 0 and stripped stdout nonempty | SHA-1 of the complete stripped output. Compare to `box.ready_note()["meta"]["digest"]` only when its ID exceeds `team.get("ready_clear",0)`. On change commit a ready note with `what="ready", digest`, using “ready work” plus the first 20 lines of output limited to 2,000 characters. Bind it to the quiet interval for dispatch freshness (optional note meta `quiet_id`). |
| 1, or 0 and empty/whitespace output | Set `ready_clear` to the current highest message ID with `update_team`, preserving other keys. Skip redundant writes. A → none → A must wake twice, including across keeper restart. |
| Unknown | One short pane line for that attempt with the exit status, timeout or failure. Leave the last report alone. |

A dropped ready note does not suppress the next eligible check. A held check may finish after other recipients have received messages. Its thread reports data only; the keeper main thread applies the decision with a healthy current box.

## 5. Pane, reload and exit

Timestamp pane events using local wall time. Build note summaries from classified meta (member name and event, quiet duration or ready-work note ID); never echo status detail, tracker output, message bodies or arbitrary escape sequences into pane lines/titles. Keep the existing delayed “sending (held)” behavior. Show startup, connectivity loss and recovery, committed notes, outcomes and shutdown once per change. Emit OSC 2 directly to stdout with flush and no newline, only when the computed title changes. Keep `emit` for scrollback lines. Priority: `keeper · N pending` (recipient pairs), else `keeper · quiet Nm` during a known quiet interval already reported, else `keeper`. No spinner or OSC 7501.

Every 30 monotonic seconds compute the same twelve-character SHA-1 of `SCRIPT.read_bytes()` that initializes `VERSION`. If different, drain in the existing terminal. While draining, continue beating, settling results and retrying withheld sends. Stop making claims or notes, and launch no new check. Let an already running check finish within its remaining `READY_TIMEOUT` (at most 30 s). Keep beating, discard its result and then exec. An upgrade does not need a subprocess cancellation interface. New ordinary messages remain pending. An entry in `self.unsettled` holds the exec while the keeper beats and retries the original result. Once `self.inflight` and `self.unsettled` are empty and the ready check has finished, call `os.execv(sys.executable, [sys.executable, str(SCRIPT), "keeper", "--state", str(self.state)])` without explicitly unlocking. A successful exec closes the close-on-exec fd and releases the flock. The new image reacquires it in `run()` in the same terminal. During this interval `ensure_keeper` sees that live terminal and its fresh beat. A failed exec leaves the existing lock held. When the team is down and its ordinary exit criterion is satisfied, let it stop; a signal still takes precedence over reload. A version-read failure keeps the current keeper working. A failed exec emits a bounded diagnostic and resumes serving; retry the version check on the next interval. `ensure_keeper` already spares a healthy old-version keeper. Keep that behavior.
