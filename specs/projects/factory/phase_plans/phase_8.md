## 1. What to run and what counts

Use eight profiles. Run Claude Code (`claude`) and `codex` as operators. Run `claude`, `codex`, `pi`, `omp`, `opencode` and `agy` as members. Cover cases 1–10 in each profile. An operator profile exercises the actual named operator, including its response to an incoming report. A member profile exercises the actual named member, including its reports and tool subprocesses. Use a Claude Code or Codex operator for the member runs and a named member for the operator runs. A second member supplies the independent sender/control when needed. The same live observation can cover both sides of the exact pairing if each side's assertion was observed. Record the peer, role, subcase and evidence ID on both rows. This is eight role profiles, not a requirement to run every possible pairing. Run the four cross cases once on real hc and rodeo. A scripted peer is appropriate for cross cases and deterministic fault injection. Disclose it by name. It cannot qualify the harness it replaces.

Extend the existing argparse entry point in `tests/live.py`. Keep the existing `check`, `fixtures` and `smoke` commands.

- `python3 tests/live.py qualify <harness> [--role operator|member] [--case N] [--json PATH]`. Omitted case selects 1–10 in order. Omitted role selects both in-scope profiles for Claude Code/Codex and member for the other four. Reject an out-of-scope role or case outside 1–10 before creating a core. Each case can start independently. A case sharing a warm team must establish its own initial conditions.
- `python3 tests/live.py qualify cross [--json PATH]` selects `two-teams`, `multi-down`, `owner-pane`, `other-version`. No role or numeric case here. Use `qualify <harness> --role ROLE --fixture [--case N] [--json PATH]` for local rehearsals on private cores. A fixture run has its own mode and can never produce an authenticated profile row.
- Emit one JSON object to stdout. Send progress to stderr. With `--json`, checkpoint the object by temporary file and replace after each finished case, retaining completed observations if the next model or provider stops responding. One runner owns one output path. Write the six human-readable reports from these outputs in the writer's worktree. Multiple remote runners need no shared manifest or database.
- Resume interrupted work with `--case N`, a fresh run ID and output path. Deduplicate imports by (mode, profile, case, subcase, run_id). Each real row carries its exact `source_head` and loaded `factory_version`. Show the newest attempt by UTC per profile/case/subcase, including a fail or not_run, and retain earlier runs as superseded evidence attributed to their own builds. For an untested subcase on a newer build, the report may cite earlier evidence with its original head. Never relabel an older result as measured on the new head. Reimporting the same run is idempotent.
- Object fields: `run_id`, `utc`, `mode` (real, fixture or cross), `source_head`, `factory_version` (actual loaded script hash, compare the keeper beat), `hc_version`, `rodeo_version`, `profiles` (role, harness, executable version, model, permission preset, peer identity), `rows`. Each row names `case`, stable `subcase`, subject role/harness, `status` (pass, fail, not_run, measured), `expected`, `observed`, `proof` (e.g. message ID, outcome transitions, changed turn, matching action count and order), and elapsed seconds when measured. Store only short allowlisted evidence. Include a reason on every fail/not_run. A prerequisite that prevents the experiment is not_run; observed behavior contrary to the asserted contract is fail. Use `measured` for the observed quit-during-hold behavior and for the three idle-latency samples. Label an unavailable measurement `not_run` with the reason. Report a separate required verdict for idle latency against SAY_WAIT. Overall exits: 1 if a required assertion fails, otherwise 2 if a selected requirement was not exercised, otherwise 0. Preserve both failure and unavailable rows in mixed runs.
- A numbered case is fail if any required subcase fails, otherwise not_run if any required subcase is missing or not_run, otherwise pass. Measurement-only rows never decide case status or the command exit code. Use unique synthetic tokens per trial, seeded separately for each sender. Ask for an action attributable to that turn, e.g. one append to a scratch receipt file with the token or a new reply containing a transformation of it. A screen that merely displays the input, a pre-existing reply in scrollback, a queued transport receipt, or the model saying it will act cannot satisfy this oracle. Never point the evaluated agent to an input file containing the expected answer to a recall or copy test. Observe the log read-only through `Log.read_box()` plus records as needed. Never forge a delivered outcome.

## 3. Ten cases, with the proof to record

1. **`states`, `startup-dialog`.** Start the installed profile in a fresh scratch project. Record hc's OSC 7501 state and turn before, during a real bounded tool action and after it, together with the independent action receipt. Catch a declared startup dialog even if already idle. Record initial state, observed dialog category and whether Factory answered a known prompt on its second matching poll or left an owner-only prompt untouched. For a profile with no declared/observed dialog record that fact from a fresh start; don't invent a dialog. Member readiness requires delivery of its real brief. An unchanged screen without an OSC report does not count.
2. **`idle-report`, `operator-commands`.** After the operator is idle, have the member run `say` to it. The report asks for a unique action. Capture sender ID, operator turn advance and action without a driver wakeup, owner Enter or second prompt. Timestamp the action separately from the transport receipt. In each real operator profile start with the candidate operator in the visible scratch project. Type the owner's prompt through rodeo asking it to invoke the absolute Factory script with `up`, `say` to a member, `status`, and `inbox --for <operator>` through its own normal tools. Have it save command exits and bounded outputs to scratch receipts; verify delivered briefs, the member's attributable action for the say, and the expected status and inbox IDs. This replaces driver-run initialization for this trial. Collect the idle-report evidence separately after the operator has finished its setup turn. Invoking the installed `/factory up` skill belongs to Phase 9.
3. **`draft`, `draft-cleared`.** Establish cleared-input latency, then type an unsent one-line owner draft through rodeo in the operator pane. Include mixed case, repeated interior spaces and punctuation in a delimited literal. While the operator is idle a member reports. Use a private `draft_wait` comfortably longer than the observed hold, e.g. 60 s. Verify a `sending` claim, the draft still intact and no report action past the LC-13 hold threshold. Submit through rodeo before expiry. Require proof of the exact literal bytes from the submitted first input (e.g. its requested copy to a scratch receipt) **and** the report action after release. Keep a byte-level control on the fake PTY as in LC-13. A trimmed or visually wrapped screen substring alone cannot prove byte equality. Once per operator profile repeat with a new draft and report, then clear the entire draft through rodeo without submitting it. Verify the report arrives and is acted on, the cleared draft causes no action, and the next deliberately submitted input has no stray characters. Preserve the keyboard operation and actual release time in the observation.
4. **`mid-turn`, `owner-interrupt`.** Give the subject a bounded task with a started marker and an externally releasable step; wait for actual `working`. Send a second unique instruction. Record turns, ordering of effects and whether the second instruction steered this turn or queued for the next. Require both expected effects for the uninterrupted trial. In a separate trial make a message pending, interrupt the operator through rodeo, release the hold/work and require the pending action once. Distinguish cancellation of the original interrupted task. If behavior is ambiguous record the evidence and repeat with a better barrier. On reproducible loss or garbling, report the profile and reproduction to @operator and use [keeper §9](../components/keeper.md)'s per-harness between-turn fallback only for that profile, then repeat with a new token.
5. **`blocked`.** Elicit an actual blocked permission/input prompt in the member under test, using a harmless scratch operation or a harness-native question. Start after the initial brief. Observe hc `blocked`, one blocked note to the operator, a queued member pair with reason blocked and no submitted test input or action there. Resolve the prompt through rodeo. Without another Factory command to prod delivery, require the same stored ID to be delivered and acted on once. Poll hc, files or the log read-only during this interval. If that harness cannot be made to report blocked in its supported mode, give the reason; a fake peer proves machinery only.
6. **`resume`, `member-switch`, `operator-switch`.** Store a secret-to-the-follow-up synthetic code word in the member's native conversation; have the member run its ready/report command. Verify the expected journal capture or per-member directory for that actual launch. Run normal `down NAME` and `up NAME`; use a fresh response that demonstrates recall without providing the code word again. Switch the member natively to a second conversation, establish a different token, then have it run its next `say`; compare the selected journal entry at down/up and the token recalled. Record what `session_follow=false` and fresh-with-notice actually do on this build. A documented fallback may pass the warning/fallback assertion while native switched-session recall stays unproved or fails. Separately switch the operator's own thread in the same terminal, keep the team, and require a fresh member report to reach and be acted on in the new operator conversation. Factory does not relaunch the owner's operator. Pair this evidence with the applicable LC probes below.
7. **`suffix`, `multiline`, `two-senders`, `pending-restart`, `held-quiet`, `upgrade`.** Send three messages from files ending exactly in `@name`, `$skill`, `/command`, with no final newline. Check the real action for each and the keeper's added wire newline on the fixture. Use a multiline body comfortably below the 64 KiB limit containing distinct markers near the beginning, middle and end; require all three in order from the recipient. In a two-sender barrier target one recipient; require both IDs exactly once in committed per-recipient order. For restart, keep ordinary work queued on a blocked recipient and one observable keeper-note episode across restart; require one eventual action per stored ID and no second note for the episode. Hold a quiet note after handoff on an operator draft, resume member work and release the hold: one late informational note is allowed, with no second delivery of it. For the version case use the cross `other-version` mechanism below; a per-profile row can cite the shared system evidence when it also identifies the actual profile it exercised.
8. **`dead-member`, `operator-gone`, `same-pane`, `unconfirmed-brief`, `quit-during-hold`.** End the member harness and leave a non-agent input recorder in its place; verify null/finished status, zero input and recovery through a replacement brief. Use only inert tokens with a nonexecuting sink in all quit trials. For the operator, leave the pane open, make a pending message observe gone, relaunch in that pane; no delivery until `up` restores reachability, then original IDs in order. In a separate run quit and restart without a pending send or a latched loss; verify the same terminal address and that the next message succeeds without `up`. 9. **`guarded`.** Configure the actual member with the published guarded preset, start it normally, then stop only that QA team's keeper and confirm it has gone. 10. **`idle-latency`, `held-sender-exit`, `crash`.** Time warm `say` calls to an idle recipient (three independent tokens; record individual monotonic times and outcomes). Report whether delivery is normally observed within `SAY_WAIT` (10 s); investigate systematic overruns with @operator before changing a default. In a separate long-hold trial let `say` exit on its own at the wait deadline, record wall time, ID and held state, then release the draft; expect one recipient action after sender exit. For the crash trial use the private keeper PID from its beat, verified against the QA terminal, and an observed `sending` claim held by hc. Force abrupt keeper death, restart with a normal Factory command, and verify one claim total, final `unconfirmed`, no second Factory dispatch. The original hc client can still type after release and order across that crash is unspecified (§8.5). Count the input and original claim separately; no automatic resend.
