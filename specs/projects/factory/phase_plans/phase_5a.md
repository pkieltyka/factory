# Phase 5a · Launch and team commands (#169)

**Outcome.** Starting in an agent's own hc terminal, an operator can check its formation, bring up selected members, receive their first replies, inspect their state, stop them and resume their native conversations. Members and keeper run headless in this phase. The operator's terminal, worktrees, other teams and message history survive down. The acceptance run uses a private core. The functional rules are in [§§5–7 and 9](../functional_spec.md), the launch sequence and adapter matrix in [launch_layout.md §§1–4, 6–8](../components/launch_layout.md), and the command output in [cli_skill.md §§1–3](../components/cli_skill.md).

Begin the live probes, adapter changes and isolated lifecycle tests while #168 builds. #168 merges first. Rebase and integrate with its real keeper and CLI before submitting #169. The owner accepts the development window between merges while skills-sync follows v1. No temporary delivery backend or production session hook. Phase 5b owns the layout document, placement, tab reuse, full adoption/recovery, leftover-file reporting and the simplification pass. LC-8 uses a test document only.

## 1. Shared interfaces and command ownership

Both architects and writers agreed to the following #168 interfaces. Use the signatures in its phase plan. Before rebase, isolated tests may supply a test double at a component boundary. The integrated path must call the actual helpers.

| #168 provides | #169 uses it for |
|---|---|
| `team_key(root)`, `state_dir(root, core)`, `open_log(state) -> Log` | Bootstrap or reopen the same state as the keeper. Computed state is `<cache base>/factory-skill/<team>/<core[:8]>`. Validate the shape, team and core of a label-sourced path before interpreting its base. An owner's cache base may be a symlink. Use the path's base even when the member has a different `XDG_CACHE_HOME`. |
| `resolve_team(args, hc) -> (cfg, state_or_None, caller_record_or_None)`, `find_team(args)` (offline-tolerant) | Find the checkout or caller's labelled team. `down`, `status` and `brief --send` use resolve_team. The repairing `up` uses `state_for(cfg,hc)` (§4.2), which does not depend on valid team metadata. Commands already attached to a team check the recorded core before any mutating RPC. Refuse another team's member/operator or a malformed label before writing. |
| `Log.locked(exclusive)`, `read_team(state) -> dict`, `update_team(state, reset=False, **changes) -> dict` | `up` supplies `v=1, root=str(cfg.root), team=team_key(cfg.root), core=hc.core, up=True`; `down` changes `up` and records confirmed intentional stops using #168’s `mark_stopped(state, terms, box)` (§4.4). Use reset only when an otherwise authorized up rebuilds unreadable metadata. Normal updates preserve unrelated keys, including later `layout` and `ready_clear`. Metadata operations under this directory lock use the yielded fd and descriptor-relative I/O. Never call a public Log operation or another lock-taking metadata helper inside it. `up.lock` is a separate nonblocking lifecycle lock. |
| `ensure_keeper(cfg,state,hc,view,force=False) -> str \| None`, `read_beat(state) -> (pid,version,term,age) \| None` | `up` starts the keeper with force; `status` calls the non-forcing path. Use #168's `KEEPER_START` (5 s) for a keeper it starts; an observed exit raises `Problem`. Status owns the keeper and operator-reachability lines. |
| `wait_outcomes(log,ident,recipients,offset,timeout=SAY_WAIT)`, `outcome_lines(outcomes,operator,sender) -> (lines, exit_code)`, `pending_lines(state,operator,now=None)` | Wait for the first brief and ordinary rebrief; distinguish a stored ID from a failure to observe a receipt. `pending_lines` owns pending counts, the inbox pointer, uncommitted count and log diagnosis. Call pending_lines directly and remove the transitional print_pending wrapper. The command prints the stored message ID before rendering outcome_lines. Even `timeout=0` does one read with no sleep. Keep the accepted Phase 4 cold-start output; omit v1 unread/wait instructions. |

Use #168's public `Log.open_dir(create) -> int | None` for the lifecycle lock. It returns the verified state directory descriptor without taking a flock; the caller closes it. For the lifecycle lock, open `up.lock` relative to that fd with `private_open` and `O_RDWR | O_CREAT`. Keep the resulting file descriptor locked with `LOCK_EX | LOCK_NB` for the command. The team directory flock is held only around metadata or log operations. #168's keeper gives a pending brief precedence on an unbriefed terminal and uses delivered terminal IDs from `Box.briefed()` before handing off held messages.

#169 owns the rest of `cmd_up`, `cmd_status`, all of `cmd_down` and `cmd_check`, plus one insertion in #168's `cmd_say`: after identifying a member on the expected core, before validating recipients or reading a message, call `record_session(cfg, state, member, term, environ=os.environ) -> str | None`. Print a returned warning on stderr and proceed. The operator records nothing. At rebase keep #168's parser, keeper, inbox command, pending summaries and tests; replace only the old launch workflow. Check both phase acceptance suites together. The abrupt-keeper-crash ordering limit in functional_spec.md §8.5 is #168's.

For `brief NAME`, take the state from `find_team(args)`; if absent render literal display-only paths `<state>/messages/<name>` and `<state>/<name>.md` (substitute the member name) and print once on stderr: `paths are final after factory.py up`. Actual launches always use the resolved directory. #168 removes both operator_wait keys, their helper and the v1 operator-support gate. Add only the session, model compatibility, dialog and env fields selected by the checks. Preserve v1 formation syntax.

**Session interface.** Implement `saved_sessions(state) -> (newest_by_member, skipped_count)`, `record_session(cfg,state,member,term,environ=os.environ)`, `launch_entry(state,m,term,how,value)` and `session_plan(m,state,entry,fresh) -> {args,resume,assigned,notice}` per launch_layout §3. Records in `sessions.jsonl` contain member, harness, model, terminal address, how, value and UTC time. Under the team directory lock (`LOCK_EX` across the read/decide/append; `LOCK_SH` suffices for a standalone planning read), validate incoming ID against the specified 1–128 character grammar; skip damaged stored entries, count and report. Complete an existing torn line with a newline before appending one encoded record, check the write count, then fsync. Open relative to the lock fd with the existing private file helper. A failed member capture is a warning and cannot prevent a message. Down's open/appendability and sync preflight happens before stopping **any** member, even when a member has no usable ID. No ID is acceptable; a storage failure is not.

Keep the newest entry for each configured member in this team's directory. Only a delivered startup brief creates a launch fallback. If the ready reply saved an env entry for the same terminal first, preserve it. With `session_follow=false`, first env capture may replace the same terminal's `new/id/dir` launch entry; later env values from that terminal are ignored. A fresh launch invalidates the earlier terminal's ID with its own `id`, `dir` or `new/null` record. Test both write orders, refused say capture, concurrent records, damaged tail, no old conversation resurrected, cross-team isolation and incompatible harness/provider. pi/omp directory strategy reads no env unless the LC-6 fallback is explicitly selected.

**Native argv.** Use launch_layout §3 table and measured exceptions; args stay separate all the way to `Hc.run`. Claude keeps prompt/settings and fresh UUID or by-ID resume. Codex uses `--no-daemon`, native `resume <id>`, `-C` and guarded `--add-dir <state>`. pi/omp get their own session paths and only compatible resumes get `--continue`. OpenCode retains standalone/model environment; agy retains model/thinking and one merged settings argument. The provider comparison is the model prefix before the first slash only for harnesses configured `resume_model="provider"`; do not silently reuse IDs across harnesses. **Readiness.** `start_member(cfg,state,hc,m,operator,sess) -> terminal` creates private files/workspace folders and starts the executable directly with the member's worktree cwd, PATH and adapter env; no shell command, no hc parent. Set only `factory.team/kind/member/dir` and `name=@<name>`, no `herdr.*` placement labels. `await_ready(hc,started,timeout=LAUNCH_TIMEOUT,clock=time) -> {member: reason_or_None}` takes a mapping from name to a pair (terminal record, configured dialogs). The caller builds that pair from the result of start_member and the launch plan's harness table. Poll all outstanding terminals including fast peers every 0.5 s against monotonic deadlines. Use hc's address/status; working waits, finished settles with cause and final output line when available. For every nonworking live state, including null or idle, normalize screen whitespace and check only known startup dialog text. A configured answer is sent once per dialog per launch. An empty answer yields the owner-action reason without sending a key. Idle with no remaining dialog alone admits the first brief. Timeout or status/read failure names member and cause; other members continue. An attempted native resume that exits before readiness retries fresh once. Give the fresh terminal a full timeout from its start and poll it with other outstanding members. Remove the failed resume's finished record by address with `hc.rm` once the fresh terminal exists. The failed resume leaves no launch entry. A trust dialog or timeout alone does not trigger fresh retries.

## 4. Commands after rebase onto #168

1. **check.** Preserve v1 selected-member model, worktree and permission diagnostics. 2. **up preflight.** Replace `require_herdr`, caller/agent lookup and pane/team discovery with identified hc caller and `team_view`. Validate names and positive timeout in seconds; default `LAUNCH_TIMEOUT`. Require `HC_TERMINAL_ID`, supported core and nonnull OSC status. Build `Config` from the requested checkout. Use `state_for(cfg,hc)` to choose the matching team's validated `factory.dir`, or compute the path from the checkout root and current core. Do not use `resolve_team` for this bootstrap: that helper requires valid metadata for a labelled caller. Take `<state>/up.lock` with nonblocking exclusive flock for the command's full run. Under it re-read caller and current view, then `check_operator(cfg, team, me, view)` before mutation. Refuse another team's labelled caller, this team's keeper/member and another reachable operator. Preflight *all* selected not-started/gone members before marking anyone or creating worktrees. Exit 2 on refusal, contention or preflight failure. Only lock bootstrap may create files before preflight. No creation/restart on `--fresh` for already-live members.
3. **up launch.** `mark_operator(cfg,hc,team,me,view,state)` marks old unreachable operator lost as needed and labels the actual caller reachable; after successful preflight initialize a missing file normally, preserve keys in valid metadata, or repair unreadable metadata with `update_team(state,reset=True,v=1,root=str(cfg.root),team=team_key(cfg.root),core=hc.core,up=True)`. A foreign core/team/path still refuses. Print the §4.5 interrupted line for each gone member before replacing its record. Create needed worktrees independently; ensure the keeper is available, then start selected members. For a gone target, identify its old terminal by address; only remove the old record once the new terminal exists, killing an old live shell if necessary. Never start another terminal for a member already starting. Collect readiness as a group. Append one first brief per ready member, using newly rendered standing instructions and v1 ready/pickup/new-conversation closings. Keeper supplies the wire sender tag; avoid duplicate tags. Append all ready members' briefs before waiting. Use one monotonic `SAY_WAIT` deadline for the batch and pass the remaining time (zero if expired) to each `wait_outcomes`. Read each current outcome even at zero time so a slow first member cannot hide a later delivery. Save a session fallback only on delivered to that launch's terminal; sending/queued/unconfirmed are not confirmation. Report each stored brief ID. If it is still sending or queued at timeout, report its reason, how to clear it if known, and `factory.py status`; the keeper still owns that ID. If no brief was enqueued (e.g. an unresolved startup dialog), name the action and then `brief --send NAME`. For a terminal with a final unconfirmed/dropped brief, tell the operator to check the recipient before explicitly rebriefing. Exit 3 for any member that failed start, readiness or confirmation. Only previously running members that still have a live terminal receive first-time join news. Rerunning up must not resend a delivered brief or old work. Keep #168's pending summary, no cold-start v1 unread line. Defer 5b placement and leftover file sweep.
4. **down.** Same lifecycle lock, fresh view, only the actual operator can stop selected members. Check session-storage viability before the first stop. Mark each live target with `factory.down=1` before kill. Once the kill succeeds or an already-finished member is selected, call `mark_stopped(state, [address], box)` with a full box from `log.read_box()`, before removing the terminal record and before dropping its queued pairs. A failed kill records no stop evidence. If evidence cannot be saved, report the address, keep its record for retry and exit 1. An `up` replacing a lost terminal never records intentional stop evidence. Document this order in launch_layout.md §6. Address only matched team member IDs; continue past an individual failure and exit 1. For confirmed stops use `log.drop_queued(box, names, why="stopped by down")` with the full box from `records, box = log.read_box()`. It refreshes the box under its own directory lock; an in-flight sending result belongs to the keeper. A stop of an absent member is idempotent. Exercise a delayed pre-typing refusal in both orders around the stop marker: an earlier requeue is dropped by the sweep; a later result is dropped by #168 under the directory lock. A receipt remains delivered and an uncertain result remains unconfirmed. Re-read the view, mark `up=False` only when the last member is down. Keep worktrees, state, operator and other teams intact; keeper handles its own exit. No layout edits.
5. **status.** Print loaded VERSION and #168's module-level SCRIPT path, hc version/team, then configured operator and members in formation order. Use `View.terminal/finished/state` and `turn`; distinguish never reported (starting) from reported then null (gone). Print interruption with cause, last observed `factory.last` or state unknown, and `box.last_to(name)` if available; no transcript guess and no resend. Keep the table available on log damage. Add shared pending lines, keeper heartbeat/version/age and headless state, operator reachable/lost, blocked/gone hints, strays and the log-size warning above 64 MiB. `ensure_keeper(force=False)` keeps a down team with no pending operator work stopped.
