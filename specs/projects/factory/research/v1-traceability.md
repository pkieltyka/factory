**80 trace rows: 61 kept, 19 dropped, 0 missing.** The final recheck closed S05, S07, S14, F11, F22 and H11, and resolved the related OSC and delivery notes.

This checks the [v1 inventory](v1-inventory.md) at baseline [v1.0.0](https://github.com/pkieltyka/factory/tree/eabfe9a11374ba8bfd99adef52a3bb238da9820a) against the [functional spec](../functional_spec.md) as read on 26 November 2026 (SHA-256 `9f121c65924280b5136831918c4b2c499e2c2da1eedf7519829199d69ea46ead`). The final pass rechecked the six outstanding outcomes and their related notes against this revision. The findings describe requirements on paper. The owner’s hc sessions were not accessed.

**Kept** identifies a section preserving the observable behavior, including explicitly inherited v1 formation, roles, harness settings and workflow. **Dropped** gives the replacement or the reason the old mechanism no longer applies. **MISSING** identifies an applicable behavior without an adequate or internally consistent requirement. Repeated evidence for the same behavior appears on one row. An issue that motivated several guarantees appears on each relevant row. Inventory line numbers refer to the linked inventory. Note links and issue numbers identify primary evidence. The final table audits the source of agent decisions independently of those counts.

The v1 implementation that distinguishes a refused append from an uncertain one, protects a managed draft and orders acknowledgement before compaction is [Inbox and draft handling](https://github.com/pkieltyka/factory/blob/eabfe9a11374ba8bfd99adef52a3bb238da9820a/skill/scripts/factory.py#L253-L494). ## What OSC 7501 can establish

All six installed harnesses have native OSC 7501 support. Root `status.state` is the source for working, idle, done, blocked and error. The core derives `turn` from those transitions. The §10 live matrix remains a qualification requirement. The six categories below cover decisions in the draft that use other evidence, including legitimate Factory workflow and transport inputs. They are separate from the trace-row counts. [hc capabilities §§3.1, 6.2–6.3 and 10](hc-capabilities.md)

| ID | Spec decision | Evidence, limit and consequence |
|---|---|---|
| A1 | §§1a, 6.3 choose whether to send a brief or answer a startup dialog. | §§1a, 6.3 limit the screen check to known startup dialogs. It covers silent Codex trust, a dialog reporting blocked and an idle-looking dialog. The first brief requires OSC idle and a cleared screen check. |
| A2 | §§5.2, 6.1–6.2, 7.1–7.4, 8.2, 8.4, 9.1–9.3 identify and stop a member, route a note, adopt the operator or flag interrupted work. | §1a limits OSC exclusivity to current agent runtime state. Team/member labels and hc terminal records establish identity. Terminal lifecycle, parent, notes configuration and intentional shutdown govern routing and interruption. §7.4 combines liveness with root status for reachability. §10.8 tests a harness exiting during draft_wait. Client-owned herdr.seen stays separate. |
| A3 | §§1a, 6.4, 8.5, 10 infer message delivery or processing. | §§1a, 8.5 use a transport receipt. §10 tests processing through an action specific to the payload. §6.4 delivers ready replies individually and allows one to steer the current operator turn, consistent with §8.3. |
| A4 | §§2, 5.1, 8.1–8.3, 10.3–10.4, 14 decide when/how to type. | §§1a, 2, 8.1–8.3, 14 distinguish hc input tracking and draft_wait from OSC state. Registered caller identity supplies attribution. Live qualification selects any idle-only policy, and the recipient’s OSC idle state releases its queued message. |
| A5 | §§4, 5.2, 6.4, 8.5, 9.4, 10.6 decide assignment readiness, resumption and pending-work recovery. | §§1a, 6.4, 8.5–8.7, 9.4–9.6 distinguish the sources of assignment readiness, resume and retry. A fresh ready/pickup reply, a saved native conversation ID, intentional shutdown and durable per-recipient outcomes provide the workflow evidence. |
| A6 | §§1a, 4, 9.4, 10 decide harness support and launch flags. | §1a removed the unsupported claim that Codex requires --no-daemon to emit OSC 7501. Its remaining statement about silent Codex trust matches the verified probe. §§4, 10 distinguish installed harness facts from live qualification of all six in both roles. |

The narrow claim supported by §1a is that Factory takes **agent-reported runtime state** exclusively from OSC 7501 via hc. Terminal identity, lifecycle, transport success, draft ownership, native conversation identity and a member’s explicit reply each answer a different operational question.
