# Factory v1 inventory for the hc port

Factory can reuse the formation, roles, Git worktrees and operator inbox. The main porting decision is how an unread report starts a turn in the intended operator session while preserving the owner’s draft. V1 demonstrates three separate events worth specifying in v2: persisting a report, submitting input to a terminal, and receiving a reply from the intended agent. Only the last establishes that the agent processed the request.

The baseline is the clean v1 checkout at `/home/peter/Dev/pkieltyka/herdr-factory`, commit `eabfe9a` (24 November 2026, after PR #162). Runtime claims below follow the Python source and tests. Historical claims follow the commit diffs, all 21 activity notes, the three research notes and GitHub issue and PR records. The documentation comparison identifies where the written guidance differs. Live results refer to the v1 team’s recorded runs. [Pinned v1 source](https://github.com/pkieltyka/factory/tree/eabfe9a11374ba8bfd99adef52a3bb238da9820a) · [V2 overview](../project_overview.md)

## Carry-over simplified

**Operator entry points.** `skill/SKILL.md` routes bare `/factory` through setup or status and recovers gone members. `setup` is an operator conversation. The Python entry point exposes the following ten commands. The old `continue` spelling only prints a pointer to `up` and exits 2. [Skill entry point](https://github.com/pkieltyka/factory/blob/eabfe9a11374ba8bfd99adef52a3bb238da9820a/skill/SKILL.md) · [CLI parser](https://github.com/pkieltyka/factory/blob/eabfe9a11374ba8bfd99adef52a3bb238da9820a/skill/scripts/factory.py#L1707-L1786)

| Commands | V1 contract and hc boundary |
|---|---|
| `init`, `harnesses`, `check [names]`, `prompt NAME` | Initialize files, list installed harness/model choices, preflight selected members without launching, and print a member’s standing instructions. These can operate without a running multiplexer. Retain these independent paths. |
| `up [names] [--fresh] [--restart] [--no-brief]` | Inspect actual caller and name conflicts, validate all affected members before pane changes, keep live members unless restarting, and resume only compatible saved harness sessions unless fresh. `--fresh` alone leaves live members alone. V1 names a tab for the operator and splits the largest pane in a separate team tab without moving focus. Translate placement, identity and launch to hc, keeping each member’s cwd, env and argv. The batched launch check exits 2. Recorded launch or brief failures exit 3 and identify the member. The documentation audit below covers exceptions. |
| `brief [--send [all\|names]]` | Preview the configured roster offline or send to live members. Compose standing instructions from role, checkout, authority and reporting rules, then send the team brief with the current roster. A new launch requests `ready`, a compatible resume requests a new pickup line, a manual rebrief requests no reply. Successful first joins can be announced to existing members. Require the reply before assigning work. |
| `down [names]`, `status` | Stop selected live members or all. Save available session refs, recheck label, agent and pane identity before close, leave the caller, inbox and worktrees intact. V1 has a check/close race. Status shows configured settings alongside observed pane/status for every member, plus unread count or inbox error. Rebind observation and close to hc identifiers. |
| `say NAME… --file PATH` | Derive the sender from the caller’s registered pane and label. Permit direct peer contact and operator fan-out. Targets accept spaces/commas and `all` expands to other live members. Each operator-bound message appends to the inbox. Member-bound text goes through `agent prompt`. Report `queued`, `submitted`, refused or unconfirmed per recipient. Preserve the distinction between a transport result and a member’s reply. |
| `wait [names] [--seen N] [--timeout S] [--interval S]`, `inbox [N]` | Unnamed `wait --timeout 0` reads just the inbox, even after shutdown. With `--seen` it acknowledges and returns any remaining rows in the same lock scope. `inbox` rereads acknowledged history, default five. A named wait restricts lifecycle events but a report from any sender wakes it. V1 polls at five-second intervals. Background waits ignore ordinary idle transitions and return for reports or blocked/gone/closed members. Foreground waits can return on settled work. Explicit timeouts exit 4. Preserve observable events and snapshot semantics when changing the wait mechanism. |

**Identity and session lifetime.** The v1 team is discovered by joining `agent list` names with `pane list` labels, session refs and lifecycle state. Session-local standing instructions, drafts and Claude settings live under the repo cache. Inbox filenames also include the herdr session key. In contrast, the append-only `sessions.jsonl` is per repo and indexed by member. Herdr forgets refs on agent exit, so roster inspections save observations. Two herdr sessions using the same repo/member names could select each other’s refs. V2 should distinguish the factory instance, member, current pane and native conversation, and verify their lifetimes before choosing a cache key. The cross-session risk is reported, without a live reproduction. [Discovery](https://github.com/pkieltyka/factory/blob/eabfe9a11374ba8bfd99adef52a3bb238da9820a/skill/scripts/factory.py#L947-L1017) · [Session cache](https://github.com/pkieltyka/factory/blob/eabfe9a11374ba8bfd99adef52a3bb238da9820a/skill/scripts/factory.py#L1174-L1204) · [Issue #108](https://github.com/pkieltyka/factory/issues/108)

**Launch readiness.** Handling trust or approval is a harness concern. V1’s single retained screen read handles only configured Claude trust/bypass, Codex trust and agy trust dialogs. It strips whitespace to handle wrapped phrases, sends the configured keys once, and withholds the brief if the dialog persists. Idle alone was insufficient on agy. Preserve that readiness condition. Use structured readiness if a tested harness provides it, otherwise retain a narrowly scoped startup exception or surface the blocker before sending. [Launch path](https://github.com/pkieltyka/factory/blob/eabfe9a11374ba8bfd99adef52a3bb238da9820a/skill/scripts/factory.py#L1057-L1117) · [Controlled agy reproduction and fix, PR #128](https://github.com/pkieltyka/factory/pull/128)

An hc event consumed by a Python process still needs a route into the operator’s conversation. ### Findings from the commit diffs

- **Waiting has two independent filters.** A named wait originally filtered other members’ lifecycle changes. The inbox patch put unread reports ahead of that check. At HEAD a report from any sender can therefore return a named wait before roster validation. With an unreadable inbox, a named lifecycle wait without an acknowledgement can still observe members. An unnamed wait or a requested acknowledgement fails with exit 2. [Original selection change](https://github.com/pkieltyka/factory/commit/a10ddad) · [Inbox change](https://github.com/pkieltyka/factory/commit/c6ec476) · [Current tests](https://github.com/pkieltyka/factory/blob/eabfe9a11374ba8bfd99adef52a3bb238da9820a/tests/test_factory.py#L1619-L1646)
- **A cold start used to recycle message IDs.** The initial inbox could reset its watermark after an empty cold start. Recoverable acknowledgement moved the history and watermark into the same atomic update, retained them across shutdown and removed reset-on-empty. Repeating an old acknowledgement cannot retire a newer report. The later pure snapshot runs before any roster query, even with the operator pane gone. [History change](https://github.com/pkieltyka/factory/commit/e77fcd7) · [Snapshot change](https://github.com/pkieltyka/factory/commit/991f3df) · [Shutdown and ack test](https://github.com/pkieltyka/factory/blob/eabfe9a11374ba8bfd99adef52a3bb238da9820a/tests/test_factory.py#L1767-L1800)
- **Retry is per attempt and recipient.** The `say` diff distinguishes refusal before the write from uncertainty once writing starts. A mixed send can queue an operator report and refuse a peer. A targeted retry must keep the original queued ID and avoid replaying the successful send. If any result is unconfirmed, the command suppresses the retry command for the entire invocation. This is covered with literal multiline verdicts and fake transport failures. [Unified send diff](https://github.com/pkieltyka/factory/commit/d227a62) · [Mixed delivery test](https://github.com/pkieltyka/factory/blob/eabfe9a11374ba8bfd99adef52a3bb238da9820a/tests/test_factory.py#L1074-L1102)
- **An append can land while the last waiter exits.** The per-batch Codex experiment took a final inbox snapshot under the inbox mutex before releasing its waiter registration. Its tests placed an append on both sides of that boundary, including lifecycle and timeout exits, and switched threads during a partially acknowledged batch. The later per-report experiment dispatched its reminder outside the inbox lock. In either case an uncertain wake had to preserve a successful append. Keep these race cases when evaluating a new mechanism. Both reminder implementations were subsequently deleted. [Race tests and design](https://github.com/pkieltyka/factory/commit/7555f62) · [Per-report change](https://github.com/pkieltyka/factory/commit/991f3df) · [Removal](https://github.com/pkieltyka/factory/commit/53a5463)
- **Session history and inbox history have different failure policies.** Shutdown compares the whole native session reference and rechecks each target before closing it. A later observation starts on a new line after a torn session-cache record, which the reader skips. A torn inbox row instead blocks delivery until repair because it may contain the only copy of a report. [Shutdown diff](https://github.com/pkieltyka/factory/commit/5b360a4) · [Session-cache test](https://github.com/pkieltyka/factory/blob/eabfe9a11374ba8bfd99adef52a3bb238da9820a/tests/test_factory.py#L2558-L2572) · [Inbox damage test](https://github.com/pkieltyka/factory/blob/eabfe9a11374ba8bfd99adef52a3bb238da9820a/tests/test_factory.py#L1767-L1800)
